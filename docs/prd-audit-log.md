# PRD: 감사 기록 (audit log)

서버가 실행한 것과 거부한 것을 **사후에 재구성할 수 있는 레코드**로 남기는 공통 기반.
도구가 아니라 모든 도구 호출이 지나는 층이다.

## 달성 가치

- **V6: 서버 행위의 감사 가능성** — 「무슨 일이 있었는가」를 대화 기록이 아니라 서버 기록으로
  답하게 한다. V3의 보증이 승인 게이트 하나에 걸려 있고 RBAC 백스톱이 없으므로, 게이트가
  오작동했을 때 남는 마지막 층이 이 레코드다.
- **V2: 단명·최소권한 자격증명** — AC3(비노출 목록)이 기록을 통해 자격증명·Secret이 새는 경로를
  닫는다. 기록이 V2가 좁혀 둔 노출 면을 되돌리지 않게 하는 것이 이 PRD의 가장 무거운 계약이다.
- **V3: 안전한 운영(Safe-by-default)** — 수집기가 미설정이어도 서버는 죽지 않고 기록을 계속
  남긴다(AC5).

## 표면 개요

- **위치**: 도구 표면이 아니라 서버 공통 기반 — 디스패처와 게이트가 지나는 한 자리.
- **형식**: 구조화 레코드(현행 `slog` 의 key=value 확장). 사람이 읽는 프로즈가 아니라 **필드**다 —
  수집기가 필드로 질의할 수 있어야 사후 재구성이 성립한다.
- **범위 밖**: 분산 트레이싱(스팬·전파), 메트릭(`prd-metrics.md`), 기록의 보존 기간·보존 정책.
  **수집기 선택도 범위 밖이 아니다** — AC5가 「stdout 너머」만 계약하고 구체 경로는 배포 구성에
  남긴다.

## Acceptance Criteria

### AC1: 모든 도구 호출이 한 레코드를 남긴다

- **설명**: 도구 호출마다 `{시각, 도구 이름, 호출 주체, 대상, 결과}`가 **한 레코드**에 실린다.
  호출 주체는 JWT 인증이면 `sub`, API 키 인증이면 키 식별자이고(키 값이 아니다 — AC3),
  대상은 리소스 좌표(`apiVersion`·`kind`·`namespace`·`name`)를 다루는 도구에 한해 그 좌표다.
  결과는 성공·거부·에러 셋 중 하나로 갈린다. 레코드가 **호출당 하나**인 것이 계약의 핵심이다 —
  여러 줄에 흩어지면 사후 재구성이 줄 잇기가 된다.
- **달성 가치**: V6
- **검증 방법**: 각 부류의 도구를 한 번씩 호출하고, 호출당 정확히 하나의 레코드가 다섯 필드를
  모두 갖고 나오는지 확인한다.

### AC2: 게이트 판정이 같은 레코드에서 연결된다

- **설명**: 게이트 대상 호출의 레코드는 gatekeeper `request_id`와 판정을 함께 싣는다. 판정은
  **승인·거절·만료·타임아웃·통신 실패·미설정** 여섯을 구분한다 — `prd-approval-gate`가 이 여섯을
  모두 거부로 처리하므로(AC5 fail-closed), 기록이 그것을 「거부」 하나로 뭉치면 **게이트가 고장난
  것과 사람이 거절한 것을 사후에 가를 수 없다.** `AUTO_APPROVE`로 승인된 호출은 그 사실이
  레코드에 표기된다(`prd-approval-gate` AC9가 요구하는 로그 표기와 같은 출처이며, 이 PRD는 그
  표기를 **필드로** 고정한다).
- **달성 가치**: V6, V3
- **검증 방법**: 승인·거절·타임아웃·미설정 네 경로를 태우고 각 레코드의 판정 필드가 서로 다른
  값으로 갈리는지, `request_id`가 gatekeeper 쪽 요청과 같은지 확인한다. `AUTO_APPROVE`를 켠
  변형에서 표기 필드가 참인지 확인한다.

### AC3: 기록에 싣지 않는 것

- **설명**: 다음은 어떤 레코드에도 실리지 않는다 — ⑴ 발급·중계되는 자격증명 값(GitHub 설치
  토큰, Grafana 토큰, AWS 자격증명, API 키, JWT 원문), ⑵ Secret의 데이터 본문,
  ⑶ `resource_exec`·`resource_attach`·`resource_proxy`의 페이로드와 응답 본문, ⑷ 요청·응답
  본문 일반. 레코드는 **무엇을 했는가**를 적고 **무엇이 오갔는가**는 적지 않는다.
  게이트 승인 화면(`prd-approval-gate` AC3)이 경로·명령 전문을 사람에게 보여 주는 것과 다르다 —
  그것은 승인하는 사람 앞에서 한 번 소비되고, 이 레코드는 수집기에 쌓인다.
- **달성 가치**: V2, V6
- **검증 방법**: 위 네 부류가 실제로 오가는 호출을 태운 뒤 레코드 전문에서 해당 값이
  발견되지 않는지 확인한다. 자격증명은 값 그대로 검색해 0건임을 단언한다.

### AC4: 실행되지 않은 호출도 남는다

- **설명**: 인증 실패, 입력 검증 거부, 게이트 거부, 미설정 거부처럼 **클러스터나 외부 시스템에
  닿기 전에 끝난 호출**도 레코드를 남긴다. 거부가 기록되지 않으면 기록은 「성공한 일의 목록」이
  되고, 감사가 가장 필요한 순간(막혔어야 할 것이 막혔는지)에 침묵한다.
- **달성 가치**: V6, V3
- **검증 방법**: 네 종류의 거부를 각각 일으키고 레코드가 결과 필드에 거부와 그 사유를 담아
  나오는지 확인한다.

### AC5: stdout 너머 보존, 그리고 수집기 미설정 시 graceful

- **설명**: 레코드는 파드 stdout을 넘어 보존된다 — 파드가 재시작·교체돼도 남는다. 수집 경로
  (Loki / OpenSearch / 기타)는 **배포 구성으로 정하고 이 PRD가 못박지 않는다.** 수집기가
  미설정이거나 도달 불가여도 서버는 기동하고 도구는 계속 동작하며, 레코드는 stdout으로 계속
  나간다(다른 통합과 같은 graceful degradation). 반대로 **수집 실패가 도구 호출을 실패시키지
  않는다** — 기록은 방어선이 아니라 관측이며, 여기서 fail-closed를 택하면 수집기 장애가 곧
  클러스터 운영 중단이 된다.
- **달성 가치**: V6, V3
- **검증 방법**: 수집기 미설정 변형에서 서버 기동·도구 호출·stdout 레코드가 모두 정상인지,
  수집기가 도달 불가일 때 도구 응답이 영향을 받지 않는지 확인한다.
