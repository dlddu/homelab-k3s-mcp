## 1. 무엇이 문제였나 — 패스 산문이 README 를 거치지 않고 정책이 됐다

`ledger.md` 의 「범위 밖(후속)」 문단은 소급 판정을 집지 않는 사유로 이렇게 적었다:

> 사유는 README 가 2026-09-14 에 그어 둔 경계(「닫힌 PR 본문을 먼저 뒤지리라 기대하는 것은
> 복원 경로가 아니라 **희망**이다」)와 판정 절차 5번이다.

**그 문장은 README 에 없다.** 출처는 `passes/2026-09-14-resource-generic-scenario20.md:43`
이고, 같은 시점의 README 는 **반대**를 적고 있었다(`README.md`, 「복원 경로는 넷이다」):

> ③·④는 `git log`·`gh pr view`로 항상 도달할 수 있다. "나중에 찾기 번거로우니 주석으로
> 옮겨 둔다"는 이 정책이 인정하지 않는 사유다.

즉 한 패스의 판단이 **정책 본문을 거치지 않고** 이후 패스에 인용으로 연쇄하며 사실상의
경계가 됐다. 09-14 패스 자신은 이 위험을 알고 있었고 그래서 이렇게 적어 뒀다 — 「이 경계는
이 원장이 처음 긋는 것이고, 다음 패스가 다르게 판정할 수 있다 … 뒤집는다면 새 패스 문서로
하고 이 문서는 그대로 둘 것」. 이 문서가 그 새 패스다.

## 2. 답과 그 귀결

**질문**: ③(PR 제목·본문·리뷰 코멘트)·④(커밋 메시지)는 *다음 편집자*에 대한 복원 경로인가?
**답(2026-09-20, 정책 소유자)**: **그렇다.**

⇒ 「그 내용을 읽어야 할 사람은 이 파일을 고치려는 사람인데 그가 닫힌 PR 을 먼저 뒤지리라
기대할 수 없다」는 **제거를 막는 사유가 되지 못한다.** README 에 그 판정을 절로 세웠다.

**죽은 것은 09-14 경계의 첫째 줄 논거 하나뿐이고, 나머지 둘은 살린다.**

| 09-14 패스가 세운 구분 | 2026-09-20 |
| --- | --- |
| ③ 이 담는 「왜 이 PR 이 이렇게 바꿨는가」는 복원된다 → 제거 | **유지**(그대로) |
| 「다음 편집자가 닫힌 PR 을 뒤지리라 기대하는 것은 희망이다」 | **기각** |
| 앞으로의 편집을 구속하는 **서 있는 불변식**은 ③ 이 집행하지 않는다 → 유지 | **유지**(살린다) |
| PR 본문이 스스로 「주석에 적었다」고 가리키면 원본은 주석 쪽 → 유지 | **유지**(살린다) |

셋을 한꺼번에 버리면 과제거가 나고 「애매하면 남긴다」와 정면 충돌한다. 도달 가능성(③ 으로
읽을 수 있는가)과 집행(앞으로를 구속하는가)은 **여전히 다른 질문이다**.

## 3. ④ 의 자리 — 「main 에 바로 push 된 커밋」 하나

같은 답이 ④ 의 오랜 모호함도 닫는다. PR 로 착지한 변경의 경위는 ③ 이 이미 담으므로
④ 가 되풀이할 이유가 없다. ④ 가 **유일한** 기록이 되는 것은 PR 없이 main 에 바로 push 된
커밋뿐이고, 그때는 커밋 메시지 말고 도달할 곳이 없다.

**실측 (`da22caa` 기준, 최근 120커밋)**

| | 값 |
| --- | --- |
| PR 경유 착지 | 74건 |
| **main 직접 push** | **46건** |
| 그중 본문(제목·`Co-authored-by` 제외)이 있는 커밋 | **0건** |
| 46건이 건드린 파일 (전수 합집합) | **`k8s/deployment.yaml` 하나** — 이 정책의 범위 밖 |
| 46건의 제목 형태 | 전부 `chore(deploy): homelab-k3s-mcp 이미지를 <sha> …` (자동 배포 핀) |

⇒ **오늘 시점 ④ 의 적용 대상은 0 이다.** 앞선 세 패스가 ④ 칸에 전건 ❌ 를 적은 것은 판정
실패가 아니라 **대상 부재**였다. 이후 패스는 ④ 를 뒤지는 데 시간을 쓰지 않는다.

**재현**

```bash
for h in $(git log -120 --pretty=format:'%H'); do
  git log -1 --pretty=format:'%s' $h | grep -qE '\(#[0-9]+\)$' && continue
  git show --name-only --pretty=format: $h
done | sort -u
# -> k8s/deployment.yaml
```

### squash 본문에 PR 본문을 싣는 안은 채택하지 않았다

검토했고 **기각**했다. ③ 은 이미 PR 당 57~144줄(최근 머지 10건 실측)을 담고 `gh pr view <N>`
으로 항상 도달한다. 같은 내용을 커밋 본문에 복제하면 **이 정책이 금지하는 중복을 정책이
스스로 만드는 꼴**이다. ③ 과 ④ 는 경쟁이 아니라 **착지 경로에 따른 역할 분담**이다.

## 4-b. 저작 중 착지한 #158 — 이 답이 무엇을 푸는지 보여 주는 실사례

이 PR 저작 중 #158(「복원 경로 ③④ 재판정 — 뜨거운 두 행」)이 머지되며 잔량이 49 → **47** 로
내려갔다. 그 패스는 두 가지를 동시에 보여 준다.

**⑴ 제거는 또 0줄이었다 — ③④ 를 물은 네 번째 패스이고 네 번 모두 0 이다.** 이 PR 은 그

**⑵ 그런데 그 0 중 2건은 이 답을 기다리고 있었다.** #158 은 ③ **축자 확인 2건**

그 질문이 곧 이 패스가 닫는 상신이고, 답은 **「그렇다」**다. ⇒ **그 2건은 이 개정이 착지하는

⇒ 「경계가 그대로면 또 0줄이 나온다」는 이 패스의 주장은 **추정이 아니라 #158 에서 실제로
