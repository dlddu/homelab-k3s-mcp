# 2026-09-14 — `resource_*` 읽기 축 신규 4파일 (`internal/k8s/resource*` · `internal/mcp/resource.go` · `tests/integration/resource_read_smoke.py`)

판정 근거: `rct_20260914-0002`(정합성 모델 `tbm_homelab-k3s-mcp-comment-redundancy`).
원장 행: 줄 주석 #25·#26·#27, docstring #9.

PR #75(`rct_20260913-0002` — `resource_*` 읽기 축 슬라이스)가 신규 4파일로 주석 **109줄**
(줄 주석 87 + docstring 22)을 들여오면서, 판정 대신 **잔량 마커**를 올렸다. 그 선택의 이유를
원장이 축자로 적어 두었다 — 「주석 비중복성 판정이 자매 모델의 소관이고, 이 슬라이스가 겸하면
자기 PR 에서 자기 주석을 판정하는 모양이 되기 때문」. 이 패스가 그 인계를 받는다.

두 표면의 판정 커버리지가 **동시에 처음으로 100% 아래로 내려갔던 것**이 이 패스의 계기다
(줄 주석 100.0% → 93.3%, docstring 100.0% → 97.9%). 게이트는 양 지점에서 rc=0 이었다 —
R4·R8 은 `합계 + 잔량 == 실측` 만 강제하고 **잔량을 올리는 것이 적법한 순응 경로**이기 때문이다.
래칫은 *은폐를 막는* 장치이지 *판정을 강제하는* 장치가 아니다.

## 판별선

직전 패스(`2026-09-13-approval-gate-core.md`)가 고정한 선을 그대로 쓴다. 이 판별선을 **내가
발명하지 않았다는 것이 이 패스의 중요한 사실**이다 — PR #75 자신이 *같은 PR 에서* 등재 범위
(`internal/server/mcp_test.go`, 원장 #4)에 이미 적용했다: 「초안은 7개 주석이 「AC번호: 그 AC의
문언」 형태였고, 그중 **5개를 판정으로 지웠다**」. 같은 저자·같은 PRD·같은 패턴이 신규 파일에는
적용되지 않은 채 남아 있었다.

| | 판정 |
| --- | --- |
| **AC 문언을 옮긴 것에서 끝난다** | ② 저장소 문서 재진술 → 제거 |
| **「그래서 코드가 왜 이 모양인가」를 잇는 절이 붙어 있다** | 유지 |
| **상류(apiserver · client-go)의 문서화되지 않은 동작을 적는다** | 유지 — 어느 복원 경로에도 없다 |
| **관측된 실패를 적는다** | 유지 |
| **AC 포인터(`(AC4)` 류)** | **지우지 않는다** — 원장 #23 이 고정한 처리. Go 단위 테스트에는 `검증 AC:` 같은 기계 판독 선언이 없어 그 포인터가 AC ↔ 코드를 잇는 유일한 자리다 |

`docs/prd-resource-generic.md` 는 **요구만이 아니라 근거까지 적는 문서**라, 「AC 를 가리키는
주석」과 「AC 를 옮긴 주석」이 한눈에 갈리지 않는다. 직전 패스가 `prd-approval-gate.md` 에 대해
적은 난점이 그대로 반복됐다 — 그래서 제거 후보마다 **원문 문장을 한 줄씩 대응시켜** 아래 표에
남긴다. 대응하는 원문을 찾지 못하면 제거하지 않았다.

## 유지 — 줄 주석 70줄 중 53줄, docstring 22줄 전부

### `internal/k8s/resource.go` — 상류 동작과 함정

- **`tableAccept` 둘째 문단** — 「파라미터는 metav1 에서 파생한다. apiserver 는 그것을 GVK 에
  대고 맞추며 모르는 것은 「대체 표현 없음」으로 취급하는데, 헤더가 평문 `application/json` 도
  함께 제시하므로 **오류가 아니라 평범한 목록으로 답이 온다**. 그래서 오타는 실패한 요청이
  아니라 빈 표이고, 자기가 만든 Table 을 이 패키지에 먹이는 테스트는 그것을 볼 수 없다.」
  → apiserver 의 문서화되지 않은 협상 거동 + **1차 시도를 죽인 바로 그 함정**. PRD 에 없다.
- **`listParameterCodec`** — typed scheme 이 모르는 group version 의 파라미터 인코딩을 거부하고
  CRD 가 정확히 그것이라는 client-go 의 제약.
- **`mapperCache`** — discovery 가 group 당 왕복이라 한 번만 만들고, 모르는 kind 가 정확히 한 번
  무효화하는 구조. **재시작 없이 CRD 를 잡게 하는 것이 그 구조의 이유**이고 코드 형태만으로는
  보이지 않는다.
- **`resolve`** — 「추측한 경로는 「그 종류가 여기 없다」 대신 「객체가 사라졌다」로 읽히는 404 를
  만든다」. AC20 은 「추측해 호출하지 않고 거부한다」를 정할 뿐, **왜 추측이 더 나쁜지**는 적지 않는다.
- **`ListResources` 본문 첫 문장** — 「평범한 목록도 이 구조체로 오류 없이 디코드되고 모든 필드가
  0 으로 남으므로, 「네임스페이스가 비었다」와 「표가 협상되지 않았다」를 가르는 것은 본문이 선언한
  kind 뿐이다」. 이것이 **이 자리에 kind 검사가 있는 이유** 자체다.

낡았다.** 당시 사실을 적은 기록이므로 그 노트 자체는 고치지 않고, 새 잔량 노트가 정정한다.
