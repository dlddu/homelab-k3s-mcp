## 유지 (사유 한 문장)

기계가 읽는 주석과 Go 관례 최소 doc(패키지 주석·exported 식별자 1줄)은 사유를 따로 대지 않는다. 아래는 필요성 시험으로 남긴 것이다.

- `main.go` `os.Exit` 를 쓰지 않는 이유(MCP 리스너와 달리) — 지우면 지표 리스너 실패를 서버 종료로 바꿔 지표 장애가 서비스 장애가 된다.
- `main.go` `buildMetrics` — 카운터를 로그 줄에 먼저 건다는 순서 보장, 지우면 순서를 바꿔 지표 실패가 기록을 잃게 한다.
- `main.go` `buildGateReader` 의 「두 인터페이스를 한 객체가 만족」 — 왜 둘인지는 `k8s.TargetReader` 가 말한다는 지시, 지우면 합치려는 사람이 근거를 못 찾는다.
- `awsconfig` 패키지 doc — 기본 자격증명은 역할 가정에만 쓰이고 S3 읽기는 역할 자격증명이 서명한다는 구조(정본, `opensearch` 가 가리킨다).
- `awsconfig.FromEnv` 의 엔드포인트 재정의 — 한 변수가 STS 와 S3 를 함께 돌리고 경로 방식 주소를 강제한다는 것, 지우면 STS 만 실서버로 나간다.
- `github.Service` 의 「토큰으로 내주지 않는 권한을 쓴다」·`installationOwner` 의 지시·`revokeToken` 의 인증 주체(앱 JWT 가 아니라 폐기할 토큰)·`mintInstallationToken` 의 AC5 가드 위치 — 가드를 토큰이 호출자에게 가는 경로에만 두는 이유, 지우면 가드를 공용 함수로 옮겨 상태 쓰기 전용 경로가 깨진다.
- `github_test.go` 스텁 필드 의미(`nil` 이 500, 빈 값이 `account` 생략)·`sha` 생략·`gotAuth`·JWT 에코 단언 — 값의 의미가 코드만으로 안 보이고, 지우면 단언이 파생 서명 재료 누출을 놓친다.
- `grafana.defaultAPIBase` — 기준 URL 이 `/api` 까지라는 상류 규약, 지우면 호스트만 넣어 토큰 경로가 틀린다.
- `grafana.Credentials`·`Service` 의 고정 TTL·정책 — 호출에 인자가 없는 이유와 Basic 비밀번호가 하나라는 사실.
- `grafana.tokenName` — 정책 안에서 이름이 유일해야 한다는 상류 제약, 지우면 타임스탬프만으로 충돌한다.
- `grafana/exposure_test.go` 의 자격증명 사용 단언 — 발급자 토큰을 안 쓰는 구현도 통과하는 공허한 테스트를 막는다.
- `opensearch.requestTimeout` — 35초의 근거(scale-to-zero 콜드 스타트 10~30초), 지우면 값을 줄여 성공할 콜드 스타트를 끊는다.
- `opensearch.Service` 의 메서드 doc — nil 인덱스·크기 상한·자동 생성·`not_found` 의 계약, 코드 형태에서 안 보인다.
- `opensearch.FromEnv` 본문 — 리전이 서명 리전을 정한다는 것과 STS 엔드포인트 재정의.
- `opensearch.DeleteDocument` 의 404 수렴 — 반복 삭제가 실패 대신 수렴한다는 의도.
- `opensearch.do` 안의 페이로드 해시 헤더 — 상류가 요구하는 명시 헤더, 지우면 서명이 조용히 거부된다.
- `server_test`(mcp) 의 AC10 광고 부재 단언·`BuildQuery` 단언·이벤트 한 줄 요약·음성 단언·over-limit 거부·`isError` 와 JSON-RPC 구분·`idempotentHint` 보존·`CommitStatus` 인자 타입·절대 커서 — 각각 지우면 느슨한 단언이 통과하는 지점(필터를 서버가 아닌 핸들러가 하는 구현, 클램프, 전체 객체 렌더 등)을 기록한다.
- `sessionplatform` 패키지 doc·`sessionsPath` 의 버전 접두부·`kindInvalidArgument`(요청 전 거부 → 세션 불변)·`kindBusy`(유일하게 재시도 가치가 있는 거부)·`kindTooLarge`(1 MiB, 유형별 한도를 이쪽에서 못 아는 이유)·`kindQuotaExhausted` — 호출자가 재시도 여부를 가를 근거이고 상류 사실이다.
- `sessionplatform.Session`·`ReadResult`·`WriteResult`·`Service`·`ListSessions` — `pod` 부재 시점, 경로 문자열 값, 쓰기 응답에 출력이 없는 것이 계약이라는 점, 조회는 수동 읽기이고 읽기·쓰기는 대상을 활성화한다는 점.
- `sessionplatform_test.go` 의 스텁 설명(`readStub`·`writeStub`)·커서 거부 단언("요청이 없었음")·다중 바이트 페이로드·거부별 본문을 같게 두는 이유·빈 id 거부·기본값은 부재 필드에만 적용된다는 것 — 단언이 공허해지거나 상류와 갈라지는 지점.
