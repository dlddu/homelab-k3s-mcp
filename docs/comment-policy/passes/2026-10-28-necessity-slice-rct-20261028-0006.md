## 유지 (사유 한 문장)

Go 관례 최소 doc(exported 식별자 첫 문장·패키지 주석)은 사유를 따로 대지 않는다. 아래는 필요성 시험으로 남긴 것이다.

### `internal/approvalgate`
- 패키지 주석의 「선언 표는 `internal/mcp` 에 있다」 — 지우면 어떤 호출이 게이트를 거치는지를 이 클라이언트 패키지에서 정하려 든다.
- `Verdict`·`Refusal`·`unavailable` — 여섯 판정이 각각 무엇을 뜻하는가(`unreachable` 이 어떤 응답까지 품는가)와, `Verdict` 가 빈 값인 경우의 의미는 상수 이름에서 나오지 않는다.
- `Pair` 의 subresource 인라인 이유, `Config.TokenFile`(커블릿이 제자리 회전한다)·`GatedKinds`(클러스터마다 자격 증명 종류가 다르다), `FromEnv` 의 `(nil, nil)` 계약.
- `Call.Describe` — 함수인 이유와 미설정 게이트가 호출하지 않는 순서 불변식(정본), `describe` 의 빈 렌더링 처분, `Gate.Authorize`·`Decision`·`Unavailable` 의 계약 문장.
- 자동 응답 모드가 생성 시점에만 적용된다는 상류 사실(`Authorize` 안), 호출자가 기다림을 그만둔 경우를 타임아웃으로 분류하는 이유(`poll` 안), 호출마다 고유 id 를 쓰는 이유(`randomExternalID`).
- 테스트: `fakeBackend` 의 폴링 관측 이유, 실패 경로 표의 「사람이 읽는 문장과 기록이 읽는 타입이 어긋나면 안 된다」, 미설정 게이트의 두 번째 단언 이유, `Consume` 이 디스패처가 쓰는 반쪽이라는 것.

### `internal/eventlog` 와 테스트
- 패키지 주석 — 두 층이 반대편에서 쓰고 서로 import 하지 못해 모양을 여기에 둔다는 것. 지우면 `mcp` 안으로 옮기려 든다.
- `Principal`(자격 증명을 타입에 들이지 않는다)·`Method`/`ID` 형식·`Anonymous`/`Unauthenticated` 의 구분·`String` 형식.
- `Target`(빈 값도 낸다)·`Result`(셋뿐)·`Reasons`(메트릭 사전 등록과 순서)·`Gate`(`Decision` 이 `approved` 로 남는 경우)·`Record`(타임스탬프를 싱크가 찍는 이유)·`Duration`/`GateWait`(로그 줄에 안 나가는 이유)·`Fanout`·`Log`·`Attrs` 의 순서.
- 테스트: `recordingSink`·`recordText`·`failingGitHub` 의 쓰임, 거부 응답이 달라지지 않는다는 것, 자동 승인 플래그 구분, 거부 기록에서 판정이 `approved` 로 남는 이유, 자격 증명 부재 단언이 빈 픽스처에 속지 않게 응답을 먼저 확인한다는 것, 승인이 `exec` 에서 소진되어 패치가 따로 필요하다는 것, 서버 테스트가 두 층의 합류 지점이라는 것.

### `internal/github/commitstatus*.go`
- 40자 SHA 만 받는 이유(짧은 SHA·ref 는 요청 도착 시점에 다른 커밋을 가리킨다), 저장소 이름에 `owner/` 를 거부하는 이유(경로에 붙어 다른 저장소를 가리킨다), 토큰 발급이 `CreateInstallationToken` 의 가드 아래에 있는 이유, 폐기 실패를 삼키는 이유, 테스트가 성공·실패 양쪽을 보는 이유(에러 문자열이 자격 증명이 새기 쉬운 자리다).

### `internal/mcp/confine*.go`
- `resourceName` 이 한 곳에 있는 이유(선언 쪽과 제한 쪽이 어긋나면 올바른 호출이 거부된다), `invoke`·`confine`·`confinedService` 의 구성 이유(핸들러가 스스로 좁히면 잊을 수 있다 · 호출마다 선언을 푸는 이유 · 통과 메서드는 구멍이다), `declaredText`·`PatchResource`·`ExecInPod`·`ProxyResource` 의 쌍 도출 이유.
- 테스트: `exercisesPair`·`isError` 의 쓰임, 선언 밖 쌍이 승인돼도 거부된다는 것, 커버리지 점검이 새 도구를 놓치지 않게 한다는 것, 게이트 자신의 사전 읽기는 제한하지 않는다는 것.

### `internal/mcp/resource*.go`
- `parseUpdateTarget`·`parseDeleteTarget` 가 게이트와 핸들러 양쪽에서 도는 이유와 하위 리소스를 거부하는 이유, `parseManifest` 가 승인 소진 전에 불일치를 잡는 이유, 원시 JSON 을 유지하는 이유, `fieldManager` 만 받는 이유, `deletionText`·`renderWatch`·`watchEventName` 의 표현 이유.
- 테스트: 자격 증명 값 상수의 쓰임, 통제군(보통 쓰기·`Secret` 거부)이 있는 이유, JSON patch 의 값 위치, 경계값과 거부를 한 테스트에 두는 이유, 게이트가 호출되지 않았다는 단언의 근거, 이어받기 지점, `apply` 의 `fieldManager` 필수 이유.
