PR #86(`rct_20260914-0006` — 시나리오 1 전용 e2e)가 신규 파일 셋으로 주석 **58줄**
(줄 주석 33 + docstring 25)을 들여오면서, 판정 대신 **잔량 마커**를 올렸다. 직전 패스
(`2026-09-14-resource-generic-e2e.md`)가 잔량을 양 표면 모두 0 으로 닫은 **직후**의 유입이고,
그것이 원장이 적어 둔 그대로다 — 「잔량 0 은 「끝났다」가 아니라 「지금 여기서 다시
시작한다」는 뜻이다」. 이 패스가 그 인계를 받는다. **래칫이 걸림 → 잔량 선언 → 소관 모델의
재감지 → 판정 → 잔량 0 으로 한 바퀴 도는 세 번째 사례**이고, 이번에도 유입(12:16Z)에서
판정까지 같은 날 안에 닫혔다.

**게이트는 유입 전후 양 지점에서 rc=0 이었다.** R4·R8 은 `합계 + 잔량 == 실측` 만 강제하고
잔량을 올리는 것이 적법한 순응 경로이기 때문이다. 초록은 「판정이 끝났다」를 뜻하지 않는다.

### 유지 — 복원 경로 넷 밖 (22줄)

- **¶4 전수 4줄** — 「픽스처 CRD 는 서버가 뜬 **뒤에** 설치될 수 있는데 재기동이 필요 없는 것은
  종류 해석이 미지의 종류에 대해 디스커버리를 **정확히 한 번** 다시 타기 때문」은 `resolve` 의
  `for _, refresh := range []bool{false, true}` 로 복원되는 것처럼 보이지만, 이 문단이 말하는
  본체는 **그 경로에 기대지 않기로 한 선택**이다(「도구가 못 찾는 것이 「아직 안 섰다」인지
  「해석이 틀렸다」인지 구분되어야 해서」). 그 선택은 코드 어디에도 적혀 있지 않고, 지우면
  다음 사람이 `wait_for_fixture` 를 「`resolve` 가 이미 하는 일의 중복」으로 읽고 뗀다.

  「도구가 아니라 kubectl 로 재는 것은 이 전제를 검증 대상 자신으로 세우지 않기 위해서」는

   형태를 「관례 최소 요약」으로 유지했다. 이 자리를 제거 쪽으로 옮기려면 그 두 행과 **함께**
   재판정하는 것이 맞다.
2. **케이스 docstring 요약 줄 4개**(「시나리오 1 — …」) — 위와 같은 계열이고, 직전 패스가 같은

   문장이 하나라 통째로 걸린다 — 그래서 남겼다.

## ci.yml 의 포인터는 손대지 않았다

`.github/workflows/ci.yml` 의 「갈린 이유는 픽스처 파일 머리말에 있다」는 이 판정으로 한 홉
늘어난다(→ 픽스처 머리말 → 「픽스처」 절). 그 파일은 정책 **범위 밖**(`.github/workflows`)이라
판정 대상이 아니고, 포인터가 끊기지 않게 픽스처 머리말에 사유의 **주제**(「`kubectl apply` 가
종류를 해석하는 시점」)를 남겨 두었다. 범위 밖 파일을 같은 PR 에서 고치는 것은 이 패스의
범위가 아니다.
