# 범위 개정 — 포함 목록에서 「레포 전체 − 제외」로 (2026-09-26)

정합성 task `rct_20260926-0013`(모델 `tbm_homelab-k3s-mcp-comment-redundancy`). 이 패스는
**주석을 한 줄도 판정하지 않는다** — 범위를 옮기고, 새로 범위에 든 파일을 판정 축 `—` 로
등재하는 것까지가 몫이다.

## 왜 이 패스가 있는가

모델 정의가 2026-09-26 에 as-is 범위를 **포함 목록**(`main.go` · `internal/` · `tests/` ·
`scripts/`)에서 **레포 전체 − 제외 세 부류**로 바꿨다. 포함 목록은 새 디렉터리를 조용히
흘리고, 등록 시점의 판단이 경계로 굳는다.

전환 직전 상태가 그 성질을 그대로 보여 준다. 게이트는 **rc=0** 이면서

- 인쇄값 `3426줄 / 153파일`
- 모델 지문 `lines=3801 files=161`

로 **+375줄 / +8파일** 어긋나 있었다. 즉 초록은 「정합」이 아니라 **「측정되지 않음」** 이었고,
그 375줄에 대해 정의의 정합 조건(「복원 가능한 내용을 담은 주석이 없음」)은 참·거짓이 정해진
적이 없었다.

사각의 경계가 정확히 그 8파일임은 변이 프로브 둘로 못박았다(사본 트리, 원 워크트리 무접촉).

## 무엇을 바꿨는가

1. **게이트 `scripts/check_comment_policy.py`** — 실측 범위와 추출을 모델 `asIs.versionScript`
   와 글자 그대로 같게 교체했다.
   - `SCAN_PATHSPECS`(포함 목록) · `SCAN_EXCLUDE_RE` · 단일 주석 정규식을 지우고,
     `FIXED_EXCLUDE_RE`(제외 부류 ①②) + 정책 본문의 `comment-scope-exclude` 블록 +
     NUL 바이트·생성 표식 제외 + **언어군 표**(파일명 ERE → 주석 줄 ERE) + 모델과 축자 동일한
     `DIRECTIVE_RE` 를 세웠다.
   - 인구조사에 **미분류 수**를 함께 인쇄한다. 미분류는 실패가 아니라 관측 대상이고, 해소는
     둘이다 — 데이터·자산이면 정책 본문의 제외 블록에, 새 언어면 템플릿 언어군에.
2. **정책 본문 `README.md` 「범위」 절** — 포함 목록 경계를 지우고 제외 세 부류를 적었다.
   `comment-scope-exclude` 블록의 규약(줄마다 ERE 하나 · 블록 안에 설명 금지 · 부류는 블록 밖
   산문에)을 명시했다. **블록 자체는 두지 않았다** — 고정 규칙으로 걸러지지 않는 고유 제외
   후보가 없고(`미분류 0`), 정의가 블록을 「(필요하면)」으로 조건화했다.
3. **원장 `ledger.md`** — 새 8파일을 판정 축 `—` 행으로 등재하고, 「읽는 법」의 낡은 문장
   (위 표면을 정규식 한 벌로 잰다)을 언어군으로 고쳤다.

## 재현: 게이트가 모델을 맞게 재는가

**단일 등식**으로 검산한다 — 같은 트리에서

```
python3 scripts/check_comment_policy.py     # 판정 대상 주석 3822줄 / 161파일 … 미분류 0
<모델 asIs.versionScript>                   # lines=3822 files=161 unclassified=0
```

두 값이 **바이트 일치**해야 한다. 이 패스의 base 에서는 `3426/153` vs `3801/161` 로 어긋났고,
착지 뒤에는 둘 다 `3822/161/0` 이다(3801 → 3822 의 +21 은 이 PR 이 게이트 파일 자신의 주석을
늘린 몫이다 — 아래).

Python 재현이 bash 를 정확히 옮긴 것인지는 **전환 전 트리에서 먼저** 확인했다: 같은 tip 에서
두 구현이 `lines=3861 files=161 unclassified=0` 과 sha256 `e80a8e98…` 까지 동일했다.

## 옛 범위 153파일은 하나도 움직이지 않았다

추출 술어가 넓어졌으므로(`//` 만 보던 자리가 `/*`·여는 별표·`{/*` 까지 본다) 기존 행이
흔들릴 수 있다. **실측은 전건 불변이다** — 옛 범위 153파일의 `경로:주석` 줄 집합이 새 언어군
추출에서 **한 파일도 달라지지 않았고**(줄 수가 바뀐 파일 0 · 집합이 바뀐 파일 0 · 범위에서
빠진 파일 0), 델타 전량이 새 8파일이다. 검산법:

```python
# 게이트를 import 해 두 추출의 파일별 줄 집합을 직접 비교한다
old = {f: [...] for f in 옛 범위}   # 옛 정의(단일 정규식 + 옛 DIRECTIVE)
new = {f: [...] for f in 새 범위}   # 새 정의(언어군 + 모델 DIRECTIVE)
assert [f for f in old if sorted(old[f]) != sorted(new[f])] == []
```

이 불변이 **우연이 아니라 내용에 대한 사실**임은 양성 프로브로 확인했다.

| 프로브 | 옛 추출 | 새 추출 | 뜻 |
| --- | --- | --- | --- |
| 옛 범위 `.go` 에 `/* … */` 한 줄 | +0 | **+1** | 새 술어는 실제로 더 넓다 |
| 옛 범위 `.yaml` 에 `# yaml-language-server: …` | **+1** | +0 | DIRECTIVE 도 실제로 다르다 |
| 옛 범위 `.yaml` 에 평범한 `#` 한 줄 | +1 | +1 | 공통 부분은 같다 |

즉 두 정의는 서로 다른데 **이 트리의 내용에 대해서는 같은 값을 낸다.** 그래서 이 패스는
「기존 행의 결과를 바꾸지 않는다」는 정의의 요구를 구조적으로 지킨다.

**움직인 행은 둘뿐이고, 이유는 추출 정의가 아니다.** 게이트 파일 자신이 두 표면에 등재돼
있어서(`scripts/check_comment_policy.py` · `check_mock_policy.py` ·
`test_check_mock_policy.py` 한 행), 이 PR 이 그 파일을 **편집한** 만큼 줄 수·지문이 움직였다.

| 표면 | 전 | 후 |
| --- | --- | --- |
| 줄 주석 | 39줄 `e8b804ebe76e` | 60줄 `6cb1385b26d0` |
| docstring | 127줄 `9c2d8db5714d` | **138줄** `98ba796c5bf0` |

두 행의 판정 축은 전환 전에도 `—` 였고 그대로 `—` 다 — 판정을 새로 하지 않는 개정이므로
R11 의 재앵커 의무가 없다. ⚠️ docstring 행은 **줄 수가 138 로 같은 채 지문만 두 번 움직였다**
(모듈 docstring 의 낡은 문장 한 줄을 고친 몫) — 줄 수 불변을 지문 불변으로 읽으면 R6 에 걸린다.

## 왜 판정하지 않는가 (범위 밖 — 후속)

정의의 완료 기준 첫 항이 축자로 「판정 축 `—` 행으로 **등재**하고, 판정은 슬라이스 예산대로
**이어 간다** … 큰 격차는 예상된 것이다」라고 적는다. 즉 이 task 의 의무는 등재이고 판정은
다음 슬라이스로 명문 이월돼 있다.

구조적 이유도 같은 방향이다. 판정으로 주석을 지우면 **방금 만든 8행의 지문이 같은 PR 안에서
움직여** 위 단일 등식이 「등재값 == 실측」과 「실측 == 모델 지문」 두 축에서 동시에 흔들리고,
「옛 범위 전건 불변」이라는 이 PR 의 안전 논거도 그 diff 에 섞인다. 선례도 같다 — 원장 형식
이전(`rct_20260926-0012`)도 「주석을 한 줄도 지우지 않는다」로 닫았다.

**다음 슬라이스가 가져갈 것**: 위 8행 375줄의 ①②③④ 판정. 슬라이스 예산(400줄) 안이라 한
슬라이스에 들어간다. 첫 후보는 `k8s/*` 넷(80줄) — 정의가 등록 시점 지목한 중복 유형 ③
**매니페스트 재진술**의 자리이고, `.github/workflows/ci.yml` 214줄은 이 레포 최대 단일 미판정
덩어리다.
