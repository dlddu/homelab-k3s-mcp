## 항목별 — `d8fa67959048` → `1f406cf98ad0` (`internal/sessionplatform/`, 제거 4줄)

### 제거 ⑴ — `kindQuotaExhausted` doc 둘째 문장 (67–69행 → 67, −2)

```
	// kindQuotaExhausted is the control plane's 507: the session's bounded
	// output history is full, so further writes are refused for good while
	// the output already accumulated stays readable. Splitting it from
	// kindTooLarge keeps AC4's four refusals four, instead of letting two of
	// them collapse onto whatever prose the control plane happens to send.
```
→ 「Splitting it from … send.」 를 지운다(앞 문장은 그대로).

**③ #53 「새 판단은 거부 응답 매핑 하나였다」가 든다** — 「원장은 두 종류를 더하는 것이 남은 설계라고 적었지만 세 종류를 더했다 … 두 종류로
접으면 413과 507이 한 kind가 되고, 둘의 구별이 **제어면이 보내는 산문**에만 의존하게 된다. AC4가 요구하는 것은 「네 거부가 서로 구별되는
것」이라 그 의존을 구조로 바꾸는 편이 세다」. 지운 문장은 **검토하고 버린 대안(두 kind)의 기록** — 3분 표 첫째 줄의 문면 그대로다. 남는
앞 문장(507 = 쿼터 소진 · 새 쓰기는 영구 거부 · 기존 출력은 읽힌다)이 이 상수의 계약이고, 「네 kind 가 산문 없이도 갈려야 한다」는 서 있는
논증의 **소유자는 `sessionplatform_test.go` 의 `TestWriteRefusalsAreDistinctWithoutTheControlPlanesProse` doc**(744–750, 유지)이며 「네
거부」 자체는 ② `prd-session-write` AC4 다. #57 의 소유자 지정(「네 kind doc — 네 거부의 구분」)은 각 doc 의 *첫 문장*(상태 → kind)을
가리키지 이 문장을 가리키지 않는다.

### 제거 ⑵ — `ReadResult` doc 끝 두 줄 (128–130행 → 128, −2)

```
// session as it stands *after* the read. Both are carried so a caller can see
// that a single read woke a parked session and brought its pod back —
// session_read/AC2 is precisely the requirement that this not be silent.
```
→ `// session as it stands *after* the read (session_read/AC2).` — AC 포인터는 접어서 남긴다(이 레포는 「어느 AC 인가」를 유지 대상으로
다뤄 왔다).

**③ #51 AC2 행**이 든다 — 「결과에 `path`(…)와 **처리 후 세션**을 함께 실어, 읽기 한 번이 파드를 되살렸다는 사실이 응답만으로 드러납니다」.
그리고 **② `prd-session-read` AC2 48–49행**이 축자다 — 「**읽기 한 번이 스냅샷 세션의 파드를 되살렸다는 사실**이 호출자에게 드러나게
한다」. 그 위에 **③ 자기 파일**: `Service` doc(153–156)이 「the control plane activates the target before serving either, which is why their
results carry the branch they took」로 *왜 결과가 분기를 싣는가*를 인터페이스 계약으로 이미 말한다. 남는 앞부분(`path` 리터럴 셋 — #51 이
제어면 소스 `dispatchPath()` 에서 가져온 상류 값 · `Session` = 처리 *뒤*의 세션)이 이 타입의 계약이다.

### 제거 ⑶ — `WriteResult` doc 끝 절 (145행, 줄 수 0)

```
// afterwards, because a write activates its target exactly as a read does.
```
→ `// afterwards (session_write/AC2).`

⑵ 와 같은 형이다 — **③ #53** 「write는 도착만으로 대상을 active로 만들고 스냅샷을 복원시키므로」 ✅ + **② `prd-session-write` AC2 43행**
「write도 read와 같은 "접근=active화" 규칙을 따른다」 + 같은 `Service` doc. 같은 형을 다르게 판정하지 않는다(#57 이 `readPath`·`writePath`
에 적용한 규칙). `WriteResult` doc 의 **앞 다섯 줄은 남는다** — 「carries no output … That absence is the contract, not an omission」은
#57 이 `WriteSession` doc 12줄을 지운 근거로 이름을 든 소유자(셋째 줄)이고, 출력 필드가 *없다*는 것은 코드에 보이지 않는 부재의 주석
(둘째 줄 — gatekeeper 의 `Unavailable.Authorize` 와 같은 모양)이다.
