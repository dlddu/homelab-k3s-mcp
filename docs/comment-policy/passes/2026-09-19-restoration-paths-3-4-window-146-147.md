# 2026-09-19 — 복원 경로 ③④ 재판정 · 두 번째 창 (`880fe2a` → `1ee9ca8`)

`rct_20260919-0004` / `tbm_homelab-k3s-mcp-comment-redundancy`.

이 패스는 **주석을 지우지 않는다.** 이번 창이 등재한 186줄(원장 5행)에 대해
[`README.md`](../README.md) 판정 절차 3번이 **묻지 않은 두 경로**를 마저 묻고, 그 답과 **갈린
자리**를 남긴다(절차 5번이 요구하는 기록). 같은 형태의 [`2026-09-19-restoration-paths-3-4.md`](2026-09-19-restoration-paths-3-4.md)
에 이어 **하루 안에 두 번째**다 — 그래서 이 패스는 기록에 더해 **게이트 R9** 를 세운다(아래 「래칫」).

## 왜 다시 여나

창은 `880fe2a`(#145) → `0b01f08`(#146, `resource_port_forward` 등록) → `1ee9ca8`(#147,
`resource_attach` 의 stdin 결함 수정) 둘이고, 판정 대상 주석 **+186 −4 = +182줄**(2455 → 2637)을
들여왔다. 다섯 행이 모두 **작성과 같은 PR 에서 판정**해 등재했고, 계량 축은 전건 정합이다 —
원소 단위 증분이 행들의 주장 합(14+3+4+37+124=182)과 같고, 합계 마커·잔량·전체 지문·게이트
rc=0 이 부모·tip 두 지점에서 모두 맞는다.

정합하지 않은 것은 **판정 자체의 범위**다. 다섯 행의 판정 산문 어디에도 ③(PR 제목·본문·리뷰
코멘트)·④(커밋 메시지)를 검토한 문장이 **없다**(행 본문에서 「PR 본문」·「커밋 메시지」 0 히트 —
산문에 등장하는 ①②③ 은 *제거 유형* 열거이지 복원 경로가 아니다). README 는 「이 중 **어디서든**
확인되면 주석의 자리가 아니다」라고 적는다.

게이트는 이 축을 원리적으로 보지 못한다. README 스스로 「CI 게이트는 「이 주석이 중복인가」를
판정하지 않는다」라 적고, 실제로 `check_comment_policy.py` 는 부모·tip 양쪽 rc=0 이다. as-is 는
주석이, to-be 는 정책 디렉터리가 움직일 때만 변하므로 **다시 열지 않으면 영구 초록인 자리**다.

### 그런데도 **유지**다 — 그 ② 표면이 영속이 아니기 때문이다

절차 3번만 보면 네 항목은 제거 쪽이다. 그러나 확인처인 tracker 행은 **`⏳ 구현 대기` 등재**이고,
doc-tracker 규칙 6 은 그것을 이렇게 정의한다:

> **규칙 6 (구현 대기)**: … 예외(영구 면제)와 달리 **임시** 등재이므로 **별도 표**에 둔다 …
> 해제 조건이 충족되면 다음 감지에서 자동으로 1:1 판정 대상으로 복귀한다.

그리고 같은 행이 자기 철거를 예약해 둔다 — 「재저작은 그 판본을 그대로 들고 오면 되고, 그때
`(미작성)` 표기(규칙 7)와 **이 행의 철거**를 같은 PR 에서 할 것」. 해제 조건 ⑴(제품 수정)은 바로
이 창의 #147 이 충족했고, 남은 ⑵(전용 e2e 재저작)는 자매 모델 `tbm_homelab-k3s-mcp-scenario-e2e`
소관으로 **지금 진행 중**이다. `docs/test-resource-generic.md` 쪽 서술도 같은 사건의
「(미작성)」 문단이라 규칙 7 이 같은 PR 에서 손대게 한다.

**즉 이 ② 히트는 오늘 참이고 곧 사라지도록 예약돼 있다.** 지우면 남는 것은 `<-r.done` 한 줄뿐이고,
그때 그 지식은 어디에도 없다. README 「애매하면 남긴다」의 비대칭 비용이 정확히 이 형태다 —
남긴 비용은 16줄, 잘못 지운 비용은 복구 불가. **절차 5번으로 유지한다.**
