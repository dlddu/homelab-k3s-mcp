# PRD: 이벤트 기록 (event log)

도구 호출 하나하나를 **집계 가능한 레코드**로 남기는 공통 기반. 메트릭(`prd-metrics.md`)이
상한이 확정된 저차원 추세를 담는다면, 이쪽은 **메트릭 라벨이 담을 수 없는 차원**을 담는다 —
리소스 종류, 호출 주체, 시간대. 두 층의 분담은 `values.md` V6이 정한다.

## 달성 가치

- **V6: 서버 운영 통계** — 「어떤 종류를 많이 만지나」·「거부가 어느 시간대에 몰리나」처럼
  메트릭이 원리적으로 답할 수 없는 질문에 답한다. 메트릭에 그 차원을 라벨로 더하면 계열이
  폭발하므로(`prd-metrics` AC4), 고차원은 여기가 맡는다.
- **V2: 단명·최소권한 자격증명** — AC3(비노출 목록). 집계의 재료를 넓히는 일이 V2가 좁혀 둔
  노출 면을 되돌리지 않게 한다. 이 PRD에서 가장 무거운 계약이다.
- **V3: 안전한 운영(Safe-by-default)** — 수집기가 미설정·도달 불가여도 서버와 도구는 영향을
  받지 않는다(AC5).

> **이 PRD는 방어선이 아니다.** 「사고가 났을 때 무슨 일이 있었는지 재구성한다」는 성질은
> 이 레코드로 **사후에 가능해지기는 하지만**, 그것이 이 문서의 근거는 아니다. 안전 보증은
> V3(승인 게이트)의 몫이고, 여기는 fail-open이다(AC5) — 방어선으로 쓰면 수집기 장애가 곧
> 보증의 구멍이 된다.

## 표면 개요

- **위치**: 도구 표면이 아니라 서버 공통 기반 — 디스패처와 게이트가 지나는 한 자리.
  메트릭과 **같은 지점**에서 파생한다(`prd-metrics` 「표면 개요」).
- **형식**: 구조화 레코드(현행 `slog` 의 key=value 확장). 프로즈가 아니라 **필드**다 — 집계
  질의가 필드 위에서만 성립한다.
- **범위 밖**: 분산 트레이싱, 메트릭 계열(`prd-metrics.md`), 보존 기간 정책, 대시보드.

## Acceptance Criteria

### AC1: 호출당 한 레코드, 집계 가능한 필드

- **설명**: 도구 호출마다 `{시각, 도구 이름, 호출 주체, 대상, 결과}`가 **한 레코드**에 실린다.
  호출 주체는 JWT면 `sub`, API 키면 키 식별자이고(키 값이 아니다 — AC3), 대상은 리소스 좌표를
  쓰는 도구에 한해 `apiVersion`·`kind`·`namespace`·`name`이다. 결과는 성공·거부·에러로 갈린다.
  **호출당 하나**인 것이 집계의 전제다 — 한 호출이 여러 줄로 흩어지면 「호출 수」를 세는 일이
  줄 잇기가 되고, 그 순간 메트릭과 기록의 수가 어긋난다.
- **달성 가치**: V6
- **검증 방법**: 부류가 다른 도구를 호출하고 호출당 정확히 하나의 레코드가 다섯 필드를 갖는지,
  같은 구간의 레코드 수가 `mcp_tool_calls_total`의 증가분과 같은지 확인한다.

### AC2: 거부 사유와 게이트 판정

- **설명**: 거부 레코드는 사유를 싣고, 게이트 대상이면 gatekeeper `request_id`와 판정을 함께
  싣는다. 사유·판정의 값 집합은 `prd-metrics` AC2의 `reason`과 **같은 구분**을 쓴다 — 두 층이
  다르게 쪼개면 「메트릭에서 본 거부율을 기록으로 파고든다」는 동선이 끊긴다.
  `AUTO_APPROVE`로 승인된 호출은 그 사실이 필드로 표기된다(`prd-approval-gate` AC9의 로그
  표기를 필드로 고정한다) — 자동 승인 비율은 **사용 패턴 통계의 항목**이다.
- **달성 가치**: V6
- **검증 방법**: 승인·거절·타임아웃·미설정 경로를 태우고 판정 필드가 갈리는지, 같은 구간의
  사유별 레코드 수가 `mcp_tool_refusals_total`의 사유별 증가분과 같은지 확인한다.

### AC3: 기록에 싣지 않는 것

- **설명**: 다음은 어떤 레코드에도 실리지 않는다 — ⑴ 발급·중계되는 자격증명 값(GitHub 설치
  토큰, Grafana 토큰, AWS 자격증명, API 키, JWT 원문), ⑵ Secret의 데이터 본문,
  ⑶ `resource_exec`·`resource_attach`·`resource_proxy`의 페이로드와 응답 본문, ⑷ 요청·응답
  본문 일반. 레코드는 **무엇을 했는가**를 적고 **무엇이 오갔는가**는 적지 않는다.
  통계에 필요한 것은 앞쪽뿐이며, 뒤쪽은 수집기에 쌓이는 순간 V2가 좁혀 둔 노출 면을 되돌린다.
- **달성 가치**: V2, V6
- **검증 방법**: 위 네 부류가 실제로 오가는 호출을 태운 뒤 레코드 전문에서 해당 값을 **값 그대로
  검색해 0건**임을 단언한다.

### AC4: 실행되지 않은 호출도 남는다

- **설명**: 인증 실패, 입력 검증 거부, 게이트 거부, 미설정 거부처럼 클러스터·외부 시스템에 닿기
  전에 끝난 호출도 레코드를 남긴다. **거부율은 이 PRD의 주된 통계 항목이고, 분자가 기록되지
  않으면 비율 자체가 성립하지 않는다** — 거부를 빼면 기록은 「성공한 일의 목록」이 되어 건강도를
  과대평가한다.
- **달성 가치**: V6
- **검증 방법**: 네 종류의 거부를 일으키고 레코드가 결과·사유를 담아 나오는지, 성공 레코드와
  합한 수가 전체 호출 수와 같은지 확인한다.

### AC5: stdout 너머 보존, 그리고 수집기 미설정 시 graceful

- **설명**: 레코드는 파드 stdout을 넘어 보존된다 — **추세는 파드 수명보다 길다.** 파드가
  재시작·교체돼도 이전 구간을 질의할 수 있어야 「늘고 있다」는 판단이 성립한다. 수집 경로
  (Loki / OpenSearch / 기타)는 배포 구성으로 정하고 이 PRD가 못박지 않는다. 수집기가
  미설정이거나 도달 불가여도 서버는 기동하고 도구는 동작하며 레코드는 stdout으로 계속 나간다.
  **수집 실패가 도구 호출을 실패시키지 않는다(fail-open)** — 통계는 관측이지 방어선이 아니며,
  여기서 fail-closed를 택하면 수집기 장애가 곧 클러스터 운영 중단이 된다.
- **달성 가치**: V6, V3
- **검증 방법**: 수집기 미설정·도달 불가 변형에서 기동·도구 호출·stdout 레코드가 정상인지,
  파드 교체 뒤 이전 구간이 수집 경로에서 조회되는지 확인한다.
